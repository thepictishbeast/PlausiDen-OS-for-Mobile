# Duress Protocol Specification

## Overview

The duress protocol provides a mechanism for users under coercion to unlock their device in a way that appears normal but activates a decoy personality. The real personality's data remains encrypted and hidden, indistinguishable from random data on the storage medium.

## Threat Scenario

A user is compelled — by law enforcement, border agents, an abusive partner, or state security services — to unlock their device. Refusal to comply may result in arrest, detention, confiscation, or violence. The user needs to appear to comply while protecting their real data.

## How It Works

### PIN Entry

The device presents a standard PIN/password entry screen. The user has multiple valid PINs:

| PIN | Behavior |
|-----|----------|
| Real PIN | Unlocks the real personality with genuine data |
| Duress PIN | Unlocks a decoy personality that looks convincingly real |
| Scorched Earth PIN | Destroys all key material, device appears factory-reset |

### Decoy Personality

The decoy personality is a fully functional device environment:
- Has its own contacts, messages, call history, photos, apps
- All data is generated by the LFI engine to match a plausible person
- Usage patterns are maintained by Brain PD even when the decoy isn't active
- The decoy has realistic browsing history, app usage, and communication patterns
- A forensic analyst examining the decoy sees a normal person's phone

### Indistinguishability

The critical property: **there is no way to determine which PIN was entered by examining the device state after unlock.** Both the real and decoy personalities use the same encryption scheme (ChaCha20-Poly1305), the same key derivation (Argon2id), and the same storage format. The encrypted data for non-active personalities is indistinguishable from random data.

### Key Derivation

```
real_key = Argon2id(real_pin, device_salt, 64 MiB, 3 iterations)
duress_key = Argon2id(duress_pin, device_salt, 64 MiB, 3 iterations)
scorched_key = Argon2id(scorched_pin, device_salt, 64 MiB, 3 iterations)
```

Each key decrypts a different personality volume. There is no master key that decrypts all volumes. Compromising one PIN reveals only that personality.

## Behavioral Requirements

1. **No timing difference**: Unlocking with the duress PIN must take exactly as long as unlocking with the real PIN. Any timing side-channel reveals which PIN was used.

2. **No UI difference**: The unlock animation, home screen transition, and initial state must be identical regardless of which PIN was entered.

3. **No notification difference**: The decoy personality must have its own notification history. A blank notification panel after unlock is suspicious.

4. **Ongoing activity**: Brain PD must maintain the decoy personality's data even when it's not active — generating messages, browsing history, app usage — so it doesn't appear stale when unlocked under duress.

## Limitations

- The duress protocol protects data at rest. If the adversary observed the device before seizure (e.g., saw the real personality in use), the duress protocol cannot retroactively hide that observation.
- If the adversary demands all PINs, the existence of multiple unlock codes may itself be suspicious. The device should support a mode where only one PIN exists (no duress capability).
- Physical tamper detection (chassis intrusion, etc.) is out of scope for this protocol but is addressed by Scorched Earth.
